# vault-search — agentic なナレッジ検索

`vault-search` MCP（`search_vault` / `read_doc` / `index_stats`）はリランカー付きの高精度な「検索筋肉」。
このスキルはそれを使ってClaudeが**思考フロー**を回すための手順。単発で1回引いて終わりにしない。

## 思考フロー

1. **分解**：質問を答えに必要な下位の問いに分ける。
   例「Threadsの伸ばし方」→「冒頭の型」「投稿時間」「保存される条件」。

2. **多クエリ検索**：各下位問いを**言い換えも含めて2〜3通り**で `search_vault(query, k=5)` を呼ぶ。
   - 表記ゆれ・同義語を変えて投げる（例「何時に投稿」「投稿時間 ベスト」「ゴールデンタイム」）。
   - 媒体が決まっているなら `folder` で絞る（knowledge / research / accounts）。

3. **充足判定**：集まった根拠で答えに足りるか自問する。
   - 足りない観点があれば、その観点だけ追加クエリで**再検索**（最大2巡）。
   - 矛盾する根拠があれば both を提示し、新しい/具体的な方（事例 > 一般論）を優先。

4. **本文確認**：要点が抜粋だけで不安なら `read_doc(path)` で全文を読む。

5. **統合・引用**：根拠ノートのパスを**必ず引用**して結論を出す。
   - 「`knowledge/30_Insights/first-two-lines.md` より…」のように出典を明示。
   - 根拠が弱い/見つからない部分は「ナレッジに無い」と正直に言う（捏造しない）。

## 注意

- 索引はスナップショット。直前に knowledge を書き換えたら先に `python lib/index/build_index.py`（差分）を回す。
- `index_stats()` で件数・モデル・最終更新を確認できる（0件なら未構築）。
- Vault全体をファイルスキャンしない。必ず `search_vault` 経由で引く。
